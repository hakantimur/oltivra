# Oltivra — Stitch Package 07: Profile Settings and Safety

## Use

Use only after Package 06 is approved. This package defines necessary account, safety, and deletion flows without adding a social network or hidden data collection.

---

## START OF STITCH PROMPT

Apply the approved **Oltivra Design Foundation** and preserve all earlier approved visual components.

Generate **exactly six high-fidelity portrait mobile screens** for **Package 07 — Profile Settings and Safety**. Use English UI copy. Keep every action plain, calm, and unambiguous.

Do not add notifications marketing controls, contact sync, social media links, avatar/photo upload, free-text support chat, a community feed, more sign-in methods, gamified safety rewards, or features beyond the six screens below.

### Screen 1 — Settings

- Bottom navigation with **Profile** active.
- Header: **“Settings”**.
- Present a short, clean list of routes only: **Edit profile**, **Language**, **Privacy & ad preferences**, **Blocked players**, **Remove Ads**, and **Delete shared account**.
- Use clear rows with restrained leading icons; do not create a dense dashboard or add unrelated app preferences.

### Screen 2 — Edit profile

- Header: **“Edit profile”**.
- Show the current curated avatar with a route to choose another curated avatar; no upload/camera/AI generation.
- One username field, and clear factual helper text: **“You can change your name once every 30 days.”**
- Include a small name-availability state and a primary **Save changes** action.
- Do not show real name, bio, location, website, social links, or public contact details.

### Screen 3 — Language

- Header: **“Language”**.
- Separate two clear settings:
  - **App language**
  - **Question language**
- Show English as the available competitive question language in this early release state. Make unavailable choices visibly unavailable without inventing a translation feature or automatic language fallback.
- Keep the explanation concise: all players in a match receive the same question language.
- Do not add a free-form translator, flag-heavy country picker, or regional matchmaking option.

### Screen 4 — Blocked players

- Header: **“Blocked players”**.
- Show a concise list of blocked usernames and curated avatars only.
- Each item has a clear **Unblock** action, with no public profile details, private notes, reason field, chat history, or social graph.
- Include a calm empty state for when no one is blocked.

### Screen 5 — Report flow

- Header uses the contextual form **“Report player”**. The same visual component will later be reused for **Report question**; do not render a separate question-report screen now.
- Offer only concise preset reasons, for example **Inappropriate name**, **Harassment through reactions**, **Impersonation**, and **Other safety concern**.
- Primary action: **Submit report**.
- Confirmation state is understated: **“Thanks — we’ll review this.”**
- Do not provide free-text chat, file uploads, photos, screenshots, public accusation, vote system, or report rewards.

### Screen 6 — Delete shared account warning

- Header: **“Delete shared account”**.
- Use a clear, serious but calm warning: **“This deletes your account and associated personal data across connected Oltivra products.”**
- State that active matches must finish or cancel safely before deletion completes.
- Primary destructive action: **Continue to delete**.
- Secondary safe action: **Keep my account**.
- Do not make deletion playful, hide the consequence, offer discounts, force a survey, or display irreversible action without a clear warning.

### Package guardrails

- Make destructive/safety actions visually distinct without using excessive red or alarmist visuals.
- Privacy and safety are utility flows, not marketing opportunities.
- End after these six screens. Do not design purchase confirmation, rewarded-ad offer, external ad creative, connection recovery, or any other screen yet.

## END OF STITCH PROMPT
